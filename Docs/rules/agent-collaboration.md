# 에이전트 협업 절차

여러 구현 책임을 나누어 진행할 때 선택해 적용한다. 역할은 책임의 구분이며, 역할마다 별도 에이전트를 둘 필요는 없다. 작은 수정이나 하나의 책임 안에서 끝나는 작업은 메인이 역할을 통합한다. 스택별 제한은 해당 `core.md`와 협업 문서를 함께 따른다.

## 설계와 작업 분배

1. 메인이 목표, 승인된 범위, 확정된 제품 동작을 정리해 설계 에이전트에 전달한다.
2. 설계 에이전트는 관련 문서와 코드를 확인해 기존 기능·공용 요소의 재활용과 추가 범위를 정한다. 책임 경계, 외부 접점의 계약, 사용처, 파일별 편집 담당, 의존 순서, 검증 범위를 설계한다. 통합 담당도 이 단계에서 연결 가능성과 초기화·종료 순서를 검토한다.
3. 정보가 부족하면 문서와 코드에서 먼저 확인한다. 제품 의미나 책임을 결정해야 하는 부분은 근거, 선택지, 추천안을 정리해 메인을 통해 사용자에게 질문한다. 합의된 설계 안의 구현 세부사항은 담당자가 자율적으로 결정한다.
4. 메인은 설계 결과를 확인하고 각 개발 담당에게 필요한 계약과 범위를 전달한다. 독립된 구현은 병렬로 진행하며, 공용 요소 개발은 필요한 경우에만 별도 담당을 둔다.

설계 결과를 형식적인 클래스·인터페이스 증가로 치환하지 않는다. 공용화는 확인된 재사용과 책임에 근거하며, 예상만으로 불필요한 추상화를 추가하지 않는다.

## 구현과 연결

- 개발 담당은 배정된 파일과 책임 안에서 구현하고 자체 검증한다. 다른 담당의 내부 구현에 의존하거나 계약을 임의로 바꾸지 않는다.
- 한 파일은 한 시점에 한 담당만 편집한다. 공용 파일 수정이 필요하면 메인이 담당과 수정 순서를 먼저 정한다. 경로를 나누기 어려운 작업은 순차 진행한다.
- 접점 변경은 사용처와 통합 담당에게 공유한다. 변경이 확정되기 전에는 관련 가정에 의존하는 구현을 진행하지 않는다.
- 통합 담당은 설계 단계의 접점 검토에 참여하고, 관련 구현과 자체 검증이 완료되면 연결을 구현하고 통합 검증한다. 역할을 나누었다는 이유로 연결을 마지막에 처음 검토하지 않는다.

## 기획·계약 변경

변경 요청이 오면 설계 담당이 계약, 책임, 사용처와 검증에 미치는 영향을 확인한다. 메인은 변경 범위를 확정하고 관련 역할만 다시 투입한다. 영향을 받는 작업만 멈추고, 독립적인 작업은 계속한다.

확정된 변경은 관련 담당에게 같은 내용으로 공유하고 관련 문서에 반영한다. 이전 계약을 따르는 코드와 검증 항목도 함께 갱신한다. 제품 의미나 합의된 책임을 바꾸는 결정은 사용자와 논의하며, 구현 세부 변경마다 재승인을 요구하지 않는다.

## 검증과 인계

개별 구현 검증은 담당 책임의 동작과 계약을 확인한다. 통합 검증은 실제 연결, 데이터 전달, 호출 순서와 수명을 확인한다. 개별 검증 통과만으로 통합 완료를 보고하지 않는다. 공유 실행 환경의 검증은 메인이 순서를 조율하며, 검증 중인 코드가 다른 작업으로 바뀌지 않게 한다.

| 역할 | 짧게 인계할 내용 |
|---|---|
| 설계 | 확정 동작, 책임·접점 계약, 재사용·추가 범위, 파일 담당, 의존 순서, 미결정 사항 |
| 개발 | 변경 파일, 제공 접점과 사용법, 검증 결과, 통합에 필요한 조건·제약 |
| 통합 | 연결 변경, 통합 검증 결과, 남은 문제와 확인하지 못한 범위 |

메인은 인계된 변경과 검증 결과를 확인하고, 확정된 사실의 문서 반영과 최종 완료 보고·커밋을 맡는다. 사용자에게 확인이 필요한 결정은 메인이 모아서 전달한다.
