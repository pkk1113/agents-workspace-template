# UI

UI 객체·스크립트를 만들거나 이름을 짓거나, 화면의 기본 선택을 정하거나, UI 이벤트를 추가할 때 읽는다.

## UI 명명 규칙

UI 이름은 객체의 실제 역할을 드러낸다. 아래 이름은 접미사를 일괄 적용하기 위한 계층이 아니라, 역할에 따라 선택하는 명명 기준이다. 배치 방식만으로 입력 UI를 `Hud`라고 부르거나 모든 UI에 `View`를 붙이지 않는다.

- `Layout`: 씬에서 UI의 배치와 화면 전환 단위를 정의하는 컨테이너다. `DefaultLayout`, `KeyboardLayout`처럼 화면 구성을 묶고 전환할 때 사용한다.
- `View`: 화면에 표시되는 독립적인 UI 중 `Menu`, `Form`, `Slate`, `Hud`, `Bar`처럼 더 구체적인 역할로 설명하기 어려운 경우에 사용한다.
- `Menu`: 사용자의 선택 또는 명령 흐름을 제공한다.
- `Form`: 사용자의 정보 입력과 제출을 중심으로 구성된다.
- `Slate`: Radial Solver 등으로 배치되는 독립적인 공간형 UI 화면이다.
- `Hud`: 카메라에 종속되거나 Follow Solver를 사용하며, 정보를 지속적으로 표시하는 UI다.
- `Bar`: 상태나 조작 요소를 한 줄 또는 좁은 영역에 모아 표시한다.
- `Panel`: `View`, `Menu`, `Form`, `Slate`, `Hud`, `Bar` 내부에서 한 가지 책임으로 묶이는 응집도 있는 영역이다.

이 이름들은 서로 배타적인 Hierarchy 단계가 아니다. 예를 들어 `PersistentHud/DeviceStatusBar`, `LoginLayout/LoginForm`, `KeyboardLayout/VirtualKeyboard`처럼 실제 부모·자식 관계와 역할에 맞춰 이름을 정한다. 역할이 이름만으로 분명하면 접미사를 억지로 붙이지 않는다.

## 기본 선택

포인터 없이 선택 이동(포커스)으로 조작하는 UI에 적용한다. 예: 게임패드, 리모컨, 터치패드·스마트 링 같은 AR 기기 입력.

화면(Layout·Panel)을 열 때 처음 선택되는 UI는 좌상단 요소로 한다. 위아래로 배치되면 맨 위, 좌우로 배치되면 맨 왼쪽, 격자면 좌상단이다. 목록은 첫 항목을 선택한다. 목적: 화면마다 시선이 어디서 시작할지 일정하게 해서, 선택 이동만으로 조작하는 입력에서 현재 위치를 찾는 부담을 줄인다.

- 예외가 필요하면 근거와 함께 사용자와 합의한다.
- 이전 화면으로 돌아갈 때 직전 선택을 복원하는 것은 이 기준보다 우선한다.

## UI 이벤트

UI 이벤트는 사용자의 직접적인 상호작용만 전달하며, 애플리케이션 동작을 요청하거나 표현하지 않는다. `QrTrackingRequested`처럼 기능을 요청하는 이름 대신 `QrButtonPressed`, `SaveButtonPressed`, `CancelButtonPressed`처럼 UI 동작을 기준으로 이름을 짓는다.

UI 이벤트와 기능의 연결은 `composition.md`의 `Feature Composition`을 따른다. 목적: 같은 UI를 다른 기능에 재사용할 수 있게 한다.
